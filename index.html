Bug POS-1042
In Triage / Open

[POS-KDS] Offline order ticket fails to sync to Kitchen Display System (KDS) after network reconnection

Severity Critical (Sev-1)
Priority P1 - High
Component Order Management / Sync Engine
Environment Staging v2.4.1 | iPadOS 17.4 (iPad Air 5th Gen)
Reporter Abhay Khandelwal (QA Engineer)
Assignee Lead Backend Engineer (Sync Team)

Steps to Reproduce:

  1. Log in to the Cashier POS terminal with an open register shift.
  2. Add 2 combo meals with modifiers to cart ($24.50 total).
  3. Disconnect the terminal Wi-Fi connection in system settings to simulate an unexpected offline state.
  4. Proceed to checkout and tender full amount via Cash.
  5. Confirm that order #ORD-4491 is queued locally with "Offline Pending Sync" badge.
  6. Re-enable Wi-Fi connectivity and wait 60 seconds.
Expected Result

POS detects restored connection, flushes offline queue to cloud server, and routes order #ORD-4491 to the Kitchen Display System immediately.

Actual Result

POS shows "Sync Successful" banner locally, but KDS screen never receives order #ORD-4491. Ticket dropped silently from queue with error ERR_SOCKET_TIMEOUT_RETRY_ABORT.

Standard Defect Life Cycle (STLC Workflow)

End-to-end defect management governance followed across Agile sprint test cycles.

01
New
Logged by QA with steps & logs
→
02
Assigned
Triaged & allocated to Dev
→
03
Open
Root-cause investigation
→
04
Fixed
Code fix committed to QA build
→
05
Retest
QA validates fix in staging
→
06
Verified
No regression; test passed
→
07
Closed
Approved for release
Condition: Bug Still Persists
↺ Reopen

If defect fails retest or triggers regression, it transitions from Retest → Reopened → Open with updated logs.

Condition: Not A Bug / Out of Scope
✕ Rejected / Deferred

If behavior matches product specs or duplicate exists, it transitions from Open → Rejected or postponed to future sprint.
